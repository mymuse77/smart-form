# Smart Form 开发运行与部署指南

本文是当前代码的运行基线。总体架构与安全边界见根目录 `README.md`；`docs/adr/spike-report.md` 仅记录早期技术验证，不能作为生产启动方式。

## 1. 当前运行单元

| 单元 | 职责 | 默认开发地址/协议 |
|---|---|---|
| `apps/server` | OIDC、资源版本、制品签名、任务规划、命令与报告路由 | `http://127.0.0.1:3001`、`ws://127.0.0.1:3001/ws` |
| `apps/web` | Chat、状态、只读画面、人工接管与提交审批 | Vite 输出的本地地址 |
| `apps/desktop` | 唯一浏览器所有者、本地状态机、执行器调度和可靠上报 | 主动连接控制面，不开放业务监听端口 |
| `apps/browser-use-sidecar` | 只读未知站点探索 | Desktop 拉起的版本化 stdio IPC |

Desktop 按 `TENANT_ID + WORKSPACE_ID` 管理一个持久化、工作区隔离的 Chromium Profile，并独占当前任务 Target。Sidecar 和 Runner 都不能自行启动浏览器或连接用户日常 Chrome。

## 2. 环境与初始化

要求 Node.js 20+、pnpm 9+、Python 3.11+、uv 和可用的本机 Chrome。

```bash
pnpm install
uv sync --directory apps/browser-use-sidecar
pnpm db:generate
```

复制 `.env.example` 并按环境覆盖配置。不要提交访问令牌、OIDC 密钥、制品私钥、Cookie 或浏览器 Profile。

## 3. 本地开发

分别启动三个进程：

```bash
pnpm dev:server
pnpm dev:web
pnpm dev:desktop
```

需要手工查看测试页面时，再启动：

```bash
pnpm dev:sites
```

开发模式允许 `smart-form-local-dev-token`，并允许 Desktop 从回环控制面获取开发制品公钥。该 TOFU 行为在生产环境被禁用。未匹配能力包的只读任务若要使用 Browser Use，还需设置 `BROWSER_USE_API_KEY` 或 `OPENAI_API_KEY`。

Chat 创建填报任务时必须明确给出字段值，例如：

```text
填报订单，orderNumber=A-202 http://127.0.0.1:8080/write
```

填报任务只能执行已签名、已验证的声明式能力包。Runner 填完字段后进入 `WAITING_APPROVAL_SUBMIT`；只有 B/S 发送与本次 `submissionId` 匹配的审批命令后才会点击提交。

## 4. 质量门禁

提交前运行：

```bash
pnpm lint
pnpm typecheck
pnpm test:coverage
pnpm test:sidecar
```

`pnpm typecheck` 当前执行全仓构建，因此也会验证 Vue、NestJS、Electron 和共享包。端到端测试 `tests/e2e/read-write.e2e.test.ts` 使用本地 HTTP 靶场与无头 Chrome，覆盖签名读能力、写入前无副作用、人工审批后提交和检查点保存，不需要真实账号或付费 LLM。

## 5. PostgreSQL

生产控制面只支持 PostgreSQL/Prisma 持久化。生成客户端与部署已审查迁移：

```bash
pnpm db:generate
pnpm db:migrate:deploy
```

`pnpm db:push` 仅供一次性本地开发数据库，不应替代生产迁移。首次迁移位于 `apps/server/prisma/migrations/20260731000000_initial`。

## 6. 生产配置与启动

控制面至少要求：

```env
NODE_ENV=production
HOST=127.0.0.1
PORT=3001
AUTH_MODE=oidc
OIDC_ISSUER=https://id.example.com/
OIDC_AUDIENCE=smart-form
OIDC_JWKS_URL=https://id.example.com/.well-known/jwks.json
RESOURCE_REPOSITORY=prisma
DATABASE_URL=postgresql://...
ARTIFACT_TRANSPORT=https
ARTIFACT_PUBLIC_BASE_URL=https://control.example.com
ARTIFACT_SIGNING_KEY_ID=...
ARTIFACT_SIGNING_PRIVATE_KEY_B64=...
```

Desktop 至少要求：

```env
NODE_ENV=production
SERVER_WS_URL=wss://control.example.com/ws
TENANT_ID=...
WORKSPACE_ID=...
DEVICE_ID=...
DEVICE_ACCESS_TOKEN=...
ARTIFACT_SIGNING_PUBLIC_KEYS_JSON={"key-id":"base64-public-key"}
SIDECAR_EXECUTABLE=...
SIDECAR_WORKING_DIRECTORY=...
SIDECAR_ARGS_JSON=["..."]
```

控制面启动：

```bash
pnpm --filter @smart-form/server build
pnpm --filter @smart-form/server start
```

生产必须由反向代理或入口网关终止 TLS，并将 HTTPS/WSS 转发到 `HOST:PORT`。不要在 URL、WebSocket 查询参数或日志中传递 Bearer Token。Desktop 启动配置、Chromium、制品信任或 Sidecar 配置失败时会直接退出；生产首次连接控制面失败也不会降级为离线运行。

当前仓库只提供 Desktop 编译和运行骨架，尚未配置签名安装包、自动更新发布渠道和企业代码签名。发布 Windows 安装包前必须补齐这些交付基础设施，不能把 `tsc` 产物直接称为生产安装包。

## 7. 明确边界

- CDP 只绑定 `127.0.0.1`，默认动态端口。
- Web 只能看任务画面，不能向 Chromium 注入鼠标键盘事件。
- 设备短期 OIDC Token 用于身份；设备私钥仅签署本地验证证据。
- 制品执行前验证 Ed25519、SHA-256、长度、租户及运行时兼容性。
- 本轮未实现敏感页面暂停推流、截图脱敏和“服务端截图仅内存转发”策略。
- `apps/browser-use-sidecar/spike-profile-01` 可能含认证数据，不属于生产路径；是否清理须由数据所有者决定。
